# Scientific RAG on QASPER

This project builds a retrieval-augmented generation pipeline on the QASPER scientific-paper dataset. It chunks paper sections, embeds them with a sentence-transformers model, compares multiple retrieval strategies, and evaluates how often the retrieved passages contain the evidence annotated for each question.

The current workflow is:

```text
QASPER parquet files -> chunking -> embeddings -> BM25 / dense / hybrid retrieval -> reranking + generation/evaluation
```

## Project goals

- Load QASPER train, validation, and test splits from the fixed parquet revision
- Extract paper metadata and text sections for retrieval
- Build chunk-level semantic embeddings for dense retrieval
- Compare lexical, dense, and hybrid retrieval techniques
- Add optional cross-encoder reranking for stronger candidate ordering
- Measure evidence coverage with hit-rate and MRR-based evaluation
- Generate grounded answers from retrieved passages with a local model

## Setup

Create and activate a virtual environment, then install dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The project currently depends on:

- `datasets`
- `numpy`
- `sentence-transformers`
- `transformers`
- `chromadb`
- `pypdf`

## Dataset loading

The project uses the fixed QASPER parquet revision rather than the older loader that is incompatible with some `datasets` versions.

Verify the dataset loads correctly with:

```bash
python src/load_data.py
```

This prints the dataset split sizes and a sample paper.

## Checkpoint 1: semantic retrieval demo

This checkpoint demonstrates chunking, embedding, and cosine-similarity retrieval without the vector database layer.

Run with the defaults:

```bash
python checkpoint1.py
```

Customize the query, number of papers, or top-k retrieval count:

```bash
python checkpoint1.py --papers 50 --query "What datasets were used?" --top-k 10
```

Outputs are written to:

```text
data/checkpoint1_index
```

This directory contains the embedding matrix and chunk metadata for the selected papers.

## Checkpoint 2: dense RAG baseline

The second checkpoint creates a persistent ChromaDB collection, retrieves the top passages for a question, evaluates them on validation papers, and optionally generates a grounded answer.

Typical run:

```bash
python checkpoint2.py --papers 25 --evaluation-papers 10 --questions 20 --top-k 5
```

Useful options:

```bash
python checkpoint2.py \
  --papers 50 \
  --evaluation-papers 12 \
  --questions 30 \
  --top-k 5 \
  --query "How is the annotation experiment evaluated?" \
  --rebuild
```

Optional extractive fallback:

```bash
python checkpoint2.py --extractive --query "What is the main contribution?"
```

### What checkpoint 2 produces

- A persistent ChromaDB database at `data/checkpoint2_chroma`
- Retrieval metrics in `reports/checkpoint2_results.json`
- A sample answer with citations for the requested query
- Evidence-hit-rate and MRR values over validation papers

## Checkpoint 3: retrieval comparison

The latest experiment compares four retrieval strategies on QASPER validation papers:

- BM25 lexical retrieval
- dense embedding retrieval
- hybrid retrieval using reciprocal-rank fusion
- hybrid retrieval with a cross-encoder reranker

Run it with the defaults:

```bash
python checkpoint3.py
```

A more complete comparison:

```bash
python checkpoint3.py \
  --evaluation-papers 40 \
  --questions 100 \
  --top-k 5 \
  --candidate-pool 20 \
  --dense-weight 0.5
```

Disable the reranker to isolate the base hybrid method:

```bash
python checkpoint3.py --without-reranker
```

### Checkpoint 3 output

Results are saved to:

```text
reports/checkpoint3_results.json
```

The JSON payload includes:

- per-method metrics (`bm25`, `dense`, `hybrid`, and `hybrid_reranked` when enabled)
- `evidence_hit_rate_at_k`, `top_1_accuracy`, `top_3_accuracy`, and `mrr`
- latency summaries (mean, median, p95)
- an optional per-question breakdown of evidence ranks

## Evaluation metrics

The retrieval evaluation in `src/evaluation.py` measures whether a returned passage contains evidence from the question's annotated answer spans. It tracks:

- evidence hit rate at `k`: whether at least one retrieved chunk matches evidence within the first `k` results
- MRR: mean reciprocal rank of the first evidence-matching result
- top-1 and top-3 accuracy
- per-query latency in milliseconds

The comparison in checkpoint 3 uses the same evidence-overlap logic and reports method-specific numbers side by side.

## Notes

- The QASPER dataset is public; the `HF_TOKEN` warning is typically informational and not required for access.
- If a vector database already exists and the embedding model matches, `checkpoint2.py` reuses it unless `--rebuild` is passed.
- The local generation model is implemented in `src/generation.py` and can be swapped with `--generator-model`.
- The cross-encoder reranker defaults to `cross-encoder/ms-marco-MiniLM-L6-v2` and is configurable with `--reranker-model`.
